# S1E Panel — интеграция Home Assistant

Прототип интеграции `s1e_panel` для локальной панели. Владелец проекта — `alexshemr`. В manifest указан целевой репозиторий `alexshemr/ha-s1e-panel`; его публикация и доступность через HACS пока не подтверждены. Базовое подключение панели к HA по адресу и токену работает без этой интеграции.

## Установка через HACS (после публикации)

1. В HACS откройте **Пользовательские репозитории** и добавьте `https://github.com/alexshemr/ha-s1e-panel`, тип **Интеграция**.
2. Скачайте **S1E Panel**, перезапустите Home Assistant и добавьте интеграцию через **Настройки → Устройства и службы**.
3. Введите HTTPS-адрес панели, отдельный ключ сопряжения Home Assistant и отпечаток сертификата. Порядок получения ключа описан ниже.

Репозиторий пока только подготавливается локально: публикация и установка через HACS не подтверждены. Включение в общий каталог HACS — отдельная процедура. Обновление компонента в HACS не обновляет прошивку панели.

## Заставки (интеграция 0.3.0, прошивка 0.4.0)

У устройства панели есть список **Заставка**: часы (`clock`), датчики (`sensors`), погода (`weather`), фото (`photo`), перемешивание (`shuffle`). Список возможностей поступает от панели. В автоматизациях используйте стандартное действие `select.select_option` и стабильный идентификатор режима, например `sensors`.

Выбор сохраняется после перезагрузки и действует до следующего переключения. Панель сразу показывает заставку, но не обходит ночной режим и выключение экрана из HA. Активное уведомление завершается перед показом выбранной заставки. Касание открывает карточки; после бездействия возвращается выбранный режим. Датчики и фотографии настраиваются в редакторе. Со старой прошивкой список недоступен, остальные сущности продолжают работать.

[Пример автоматизации по мелким частицам](AUTOMATIONS.md#постоянная-заставка-по-уровню-мелких-частиц).

## Установка из ZIP (0.3.0)

1. Скачайте `ha-s1e-panel-0.3.0.zip` и распакуйте его на компьютере. Устанавливайте обычный ZIP, не архив `-source.zip`.
2. Откройте каталог конфигурации Home Assistant — тот, где находится `configuration.yaml`. В HA OS это `/config`; для Container — каталог, примонтированный как `/config`.
3. Скопируйте из архива каталог `custom_components/s1e_panel` в этот каталог конфигурации. Итоговый путь: `/config/custom_components/s1e_panel/manifest.json`. Если `custom_components` нет, создайте его. Не должно получиться вложенности `custom_components/custom_components`. При обновлении замените прежний каталог `s1e_panel` целиком.
4. Перезапустите **Home Assistant** (перезагрузка YAML недостаточна). В интерфейсе: **Настройки → Устройства и службы → Добавить интеграцию → S1E Panel**. Если интеграция не появилась, обновите страницу и проверьте путь из шага 3 и журнал HA. У Home Assistant нет универсальной кнопки загрузки ZIP интеграции: файлы нужно перенести в конфигурацию, например через Samba или доступ к файловой системе сервера.
5. Откройте веб-редактор панели: `https://192.168.31.191:8443` для текущего стенда. Если браузер ещё не сопряжён, на физической панели откройте «Сопряжение», введите показанный код в браузере и подтвердите запрос на панели.
6. В настройках редактора нажмите **Подключить HACS** (так называется кнопка создания ключа даже при установке из ZIP); откроется **Подключение Home Assistant**: снова откройте сопряжение на физической панели, введите свежий код, нажмите **Создать ключ**, подтвердите запрос **Home Assistant** на панели. Сохраните показанный ключ: он нужен именно интеграции. В настройках редактора нажмите **Отпечаток сертификата для интеграции** и сохраните SHA-256.
7. В форме интеграции HA введите HTTPS-адрес панели с портом `8443`, отдельный ключ из шага 6 и SHA-256 сертификата. После подключения откройте устройство S1E Panel: появятся экран с яркостью, диагностика, ночной режим и действия отправки/отмены уведомлений.

В версии прошивки **0.3.3** сохранены изменения свайпов и остановки штор из коммита `cc5e7c1` вместе с погодными уведомлениями и управлением подсветкой. Установка ZIP обновляет только сторону HA; новая прошивка панели устанавливается отдельно подписанным OTA-пакетом.

Доступны сущность экрана с яркостью, версия, сеть Wi-Fi, соединение с HA, три реле и действие `s1e_panel.show_message`. Для NPD1121WSK01 прошивка 0.3.3 инициализирует GPIO 9/10/11, после чего сущности реле доступны автоматически. Подтверждение программы не является измерением контактов.

В автоматизации выберите действие **S1E Panel: Show message**, устройство панели, текст, длительность и приоритет. Обычное сообщение ждёт заставки; приоритетное может временно включать экран. Триггеры и расписания задаются обычными средствами HA.

Ключ можно отозвать в редакторе панели. Токен HA в эту интеграцию не вводится: здесь нужен отдельный ключ сопряжения панели.

## English

Copy `custom_components/s1e_panel` into your HA configuration, restart HA and add **S1E Panel** under Devices & services. Enter the panel's HTTPS URL, a dedicated Home Assistant pairing key approved on its screen, and its certificate SHA-256 fingerprint. The integration exposes screen brightness, diagnostics, relay entities and `s1e_panel.show_message`. Firmware 0.3.3 initializes the verified NPD1121WSK01 GPIO mapping, enabling normal relay entities. A public HACS repository is pending; current manifest URLs are placeholders.

Own code: MIT. Tested against Home Assistant 2026.10.4; see the main project's validation document for remaining hardware and release work.

## Версия 0.2.0

Экран поддерживает включение, выключение и яркость. Его атрибуты `off_reasons` показывают действующие причины: `night`, `home_assistant`, `timeout`; `temporary_wake` показывает временное пробуждение. Добавлены диагностика режима экрана и бинарный датчик ночного режима. Состояние — программная уставка подсветки панели, а не измерение светового потока.

Ночь и выключение из HA действуют независимо. Включение из HA снимает только его выключение; ночью экран остаётся тёмным. Касание будит до `idle_seconds` бездействия, важное сообщение — на время показа. Обычные сообщения ждут заставки. После важного сообщения возвращается актуальное состояние. Выключение из HA прекращает активное сообщение. После перезапуска выключение из HA и очередь не сохраняются: автоматизация должна повторно установить состояние.

`show_message` принимает дополнительные `id`, `title`, `weather`, `background` (`auto`, `weather`, `plain`). Передавайте один элемент прогноза HA; единицы берутся из `weather.entity_id`, либо явно из объекта. Температура без источника и единиц использует настройки HA. Прямой API панели без единиц использует °C. Ночной фон выбирается по `night`, затем `is_daytime`, затем `clear-night`; текущая погода прогноз не заменяет. Автоматических советов нет.

ID: 1–128 символов `A–Z a–z 0–9 _ - . :`. Повторный ID заменяет сообщение и обновляет срок показа. Отмена неизвестного ID безопасна. Поля старых автоматизаций сохранены; обычный приоритет по умолчанию, 10 секунд показа и TTL 300 секунд.

### Подготовка отдельного репозитория HACS

`python tools/package_ha.py` из основного проекта создаёт установочный ZIP и архив `-source.zip`. Содержимое source-архива предназначено для корня будущего репозитория интеграции. В нём есть Linux CI: pytest, Hassfest, HACS validation. Проверенная базовая версия HA: 2026.10.4, Python 3.14.

В manifest указан владелец `@alexshemr` и целевые адреса `https://github.com/alexshemr/ha-s1e-panel`. До публикации нужно создать или проверить этот публичный репозиторий и выполнить его проверки. Брендинг и требования каталога HACS проверяются перед публикацией. Успех HACS CI и установка через HACS локальной упаковкой не подтверждаются. Публикация не выполнялась.

## Дополнения 0.2.3

В разделе диагностики устройства добавлен датчик «IP-адрес панели» из текущего сетевого состояния панели. Если адрес недоступен, датчик показывает неизвестное значение. Иконка интеграции включена в сам пакет (`brand/icon.png`, `icon@2x.png`); её источник — предоставленный пользователем `icon.svg`.

При недоступном аппаратном драйвере сущности реле показывают обычное состояние недоступности. Неизвестное состояние не подменяется выключенным. После запуска драйвера и поступления состояний каналов существующие сущности автоматически поддерживают включение и выключение. Программное подтверждение не заменяет измерение состояния контактов.
